# Публикация 0.4.0

Публикация репозитория и готового приложения на GitHub разрешена владельцем. Этот список помогает проверить содержимое и точный выпуск; он не вводит нового согласования.

## Исходники

- Использовать [проверенный список файлов](source-publication-files.txt) и [отчёт аудита](source-publication-audit-2026-09-16.md). Перед commit сопоставить с ним staged-файлы: `.gitignore` не исключает уже отслеживаемые файлы.
- В публикацию входят Swift/Python source, синтетические тесты, scripts, Resources, документация и workflow. Включение исходника legacy-коннектора не означает включение его Python runtime в обычное приложение.
- `build/`, `.venv/`, личные экспорты, runtime caches, WebKit storage, credentials и локальная конфигурация инструментов исключены.
- Лицензия собственных исходников не выбрана. **Владелец разрешил публикацию без LICENSE**; выбирать условия от его имени или называть проект распространяемым по неуказанной лицензии не нужно. Это не блокирует разрешённую публикацию. Уведомления о реально включённых сторонних зависимостях сохраняются.

## Пакет 0.4.0 build 10

1. Проверить версию 0.4.0 / build 10 в исходных plist и готовых host/widget bundles.
2. Дождаться успешного CI для Apple Silicon и Intel, включая нативные и web-контракты, отрисовку, sandbox, подписи и системные зависимости.
3. Использовать ZIP/DMG и SHA-256 именно из этого прогона. В пакетах нет Python runtime, пользовательских данных и developer home paths.
4. До публикации сравнить SHA-256 всех шести загруженных файлов с проверенными пакетами. Опубликовать тег на точный проверенный commit и отметить выпуск как latest.
5. Указать в [заметках к выпуску](releases/0.4.0.md) фактические архитектуры и границы проверки. Не выдавать синтетические тесты за живой вход Garmin или проверку системных виджетов.

Пакеты остаются ad-hoc signed без Developer ID/notarization. Установка и тесты на Mac владельца для удалённого выпуска не требуются. Проверки [0.3.0](releases/0.3.0.md) и [0.2.0](validation.md) остаются историей.
