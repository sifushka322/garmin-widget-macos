# GarminDesk 0.5.0 — candidate, build 11

This is a local source candidate. The public download remains 0.4.0 with English and Russian. The exact candidate package must pass the [normal upgrade test](../widget-upgrade-validation.md) before publication.

## Five widgets, no profiles

- **Summary** is one coherent measurement layout: a leading value and supporting daily, sport, and sleep readings. Large shows up to seven measurements. Choose its measurements and preferred main value directly in Widgets settings. The calendar remains in Training.
- **Day** shows daily energy, movement, and supporting health readings.
- **Sport** shows readiness, recovery, and training measurements, without completed or scheduled workout cards.
- **Sleep** adds duration, score, sleep stages, and related nightly readings.
- **Training** is a mini calendar: a week in small and medium sizes, a month in large. Completed and scheduled activities have different markers. A date outside retrieved coverage is unknown, not an empty schedule or a rest day.

Choose a type and size in the macOS gallery. The app's Widgets pane offers a direct preview and one shared **Colorful**, **Light**, or **Dark** appearance. Colorful uses turquoise Day, orange Sport, purple Sleep, and blue Training backgrounds. Light and Dark change the backgrounds and text contrast as well as the accent. There are no profile creation, assignment, or content-mode controls. Summary has a single shared ordered measurement selection.

Gallery previews use synthetic measurements and a sample schedule, with a localized Demo badge, so the types and sizes can be compared before connection. The app's widget preview uses the same sample when no real measurements are present. Examples follow the selected appearance, language, and Summary measurements. Added desktop widgets show actual data or a connection/waiting state; the preview factory never publishes a timeline or reads personal measurements.

Available measurements fill the limited space automatically. Summary uses only its selected measurements, in their saved order; the other measurement types use fixed purpose-specific priorities. Missing values do not occupy secondary cards; measured zero remains valid. Water and weight are not fixed defaults. This is a choice based on data availability and widget purpose, not evidence of low popularity. Retained readings keep their date context. See the [metric-selection rationale](../widget-product-decisions.md) for Garmin sources and device/data limitations.

## Upgrade and icon

The four existing WidgetKit kind identifiers remain stable and Day is added. Migration preserves language, app appearance, refresh cadence, account connection, cached readings, and calendar coverage. Old profile names, metric selections, assignments, and mixed layouts are intentionally replaced by the five purposes. Summary starts with a balanced default selection that can be changed without creating a profile. Valid old widget links still resolve to their purpose or Summary.

An old extension process can briefly outlive app replacement. A private compatibility projection in the widget snapshot keeps its four kinds readable, including a supported language fallback; standalone preferences no longer contain profiles. This does **not** guarantee that macOS replaces the running extension or gallery images immediately. The [simplification audit](../widget-simplification-audit.md) documents these boundaries and the retired optional App Intents prototype.

The icon package removes unintended translucency that caused macOS to add a gray outer plate and reduce the visible watch. The selected artwork is unchanged. Isolated icon-service comparisons passed at 32, 48, 64, and 256 pt. Actual gallery behavior after a normal upgrade remains a separate acceptance check.

## Twelve languages

The app and widgets support English, Russian, German, French, Spanish, Italian, Brazilian Portuguese, Dutch, Polish, Japanese, Korean, and Simplified Chinese.

Choose a native language name under **General → Language**, or follow the system's ordered language preferences. Existing English/Russian/system choices are preserved. Unsupported languages fall back to the next supported preference, then English. Traditional Chinese is not treated as Simplified Chinese; Portuguese variants use the Brazilian Portuguese translation. Manual choices apply corresponding date and number formatting, while the system option retains system regional settings. Names supplied by Garmin retain their original text.

## Validation and release limits

Local checks cover migration in both reader directions, fixed kinds and links, language catalogs and substitutions, selection of available readings, retained dates, calendar coverage, synchronization and account boundaries, icon packaging, and keeping releases in draft. Synthetic images cover all twelve languages, five types, three widget sizes, the three appearances, minimum-width app settings, and empty/partial/retained data states. These checks do not establish native-speaker review, live Garmin sign-in, or actual system-gallery refresh after replacement.

The local Apple Silicon build passed app/extension signature, architecture, version, system-dependency, and ZIP-content checks using SDK 26.5. Both bundles contain twelve locales; the packaged icon, license, and notices match the source assets. Passed checks include 12,737 localization assertions, 232 shared-model assertions, 34 metric-policy assertions, 214 widget configuration/preview assertions, 141 host synchronization assertions, 39 calendar assertions, 12 icon assertions, and four draft-release tests. Rendering produced 530 widget images, including every gallery type/size in all twelve languages, plus 45 calendar-state images. Representative layouts, badges, custom selections, retained dates, and live-demo rejection were visually inspected. Minimum-width app review covers 72 language/theme/appearance images plus 24 expanded measurement-editor views. This evidence is local, not a new GitHub CI run or a normal upgrade acceptance result.

CI prepares a verified draft instead of immediately publishing a release. Normal upgrade acceptance must use that exact package over the previous public release, with existing widgets left in place and without clearing caches or restarting system services. The 0.4.0 stale-gallery incident is not claimed as universally fixed.

The candidate targets macOS 14+. Local packaging uses ad-hoc signatures without notarization. The source changes and candidate package remain local; this candidate has not replaced the owner's installed app or been published to GitHub.
