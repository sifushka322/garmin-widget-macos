# GarminDesk 0.6.0

Build 12. Local release candidate; packaging and validation results are recorded
in [the release audit](../audit-0.6.0.md).

Apple Silicon DMG and ZIP packages were built and verified on macOS 26.6.2.
Native contracts, an isolated AppKit lifecycle run, sandbox sharing, synthetic
visual checks, signatures and archive checks passed. Intel and actual system
widget upgrade behavior were not validated in this local release.

## Changes

- GarminDesk runs in the macOS menu bar with a monochrome watch icon and no Dock
  icon. The menu provides settings, manual refresh, connection status and Quit.
  Closing the main window keeps automatic synchronization running.
- Metric cards and widgets include short interpretations. The information button
  in each app card explains the measurement, its period, and relevant Garmin
  guidance. Training load shows Garmin's load-ratio category and training status
  when supplied; a low number alone is never labeled detraining. HRV distinguishes the nightly value
  from Garmin's weekly status and personal baseline.
- Body Battery freshness considers the measurement time, so retrieving an old
  sample again does not present it as a fresh watch reading.
- Body Battery can use the summary's latest scalar when the report is absent or
  clearly older; a lagging report cannot replace a newer cached timed sample.
- When sufficiently recent Garmin graph points exist, Body Battery advances with
  a local linear estimate once per minute. Estimates display `≈`, expire one hour
  after the last sample, and never change the saved actual reading. Sparse data,
  a day change, or a different latest value disables the old estimate. This is a
  GarminDesk calculation from Garmin samples, **not a verified Garmin forecast**.
- Private cached snapshots are tied to their account; interrupted writes cannot
  restore the previous account's readings after switching accounts.
- Reopening a minimized Garmin sign-in window brings it back into view.

New explanatory copy is available in English and Russian. The other existing
interface languages display English explanations until translations are added.

Garmin's chronic-load limits are not presented as an acute-load optimal range.
The current verified payload provides a load-ratio category and ratio, not a
verified numeric acute-load target. See the [metric interpretation audit](../metric-explanations-audit-2026-09-19.md).

The app reevaluates estimates every minute. WidgetKit receives minute-spaced
display entries and an expiry entry, while macOS controls actual rendering.
Source-selection and estimation limits are detailed in the
[Body Battery audit](../body-battery-refresh-audit.md).

## Distribution

The application targets macOS 14+. The local package uses an ad-hoc signature
without Apple notarization. This candidate has not been published to GitHub.
Validation scope and remaining limitations are listed in the audit.
